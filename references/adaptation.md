# 文案与版面适配

排版前和逐页审稿时使用。先看信息的语义角色，再决定版式；可读性不由“文字都装下了”判断。

## 改动边界

- 默认以文案为准：保留措辞与事实，调整信息块、栏宽、字号层级、图片比例或分页。目录、日期、统计、联系方式不当作连续正文自动流栏。
- 用户明确允许润色、精简或按版面改写时，以页面任务为目标改写：可以拆长句、改成短标题＋说明、去掉重复表达；保留所有独立信息点和限定条件。
- 姓名、机构、数字、年龄、价格、时间地点、包含/不包含、拟定/已确认等事实不因排版改变。不得为凑字数新增承诺。
- 原文件及抽取原稿保留；doc.md 是本轮排版文案，new_project.sh 建项目时自动留一份 doc.original.md 作基线（已存在不覆盖）。逐项记录 copy-changes.md：原句、采用句、原因、适用页、事实核对。授权写进brief.md；冻结文案项目不走改写。
- 核对分两步：先逐项确认改写覆盖原信息、数字和限定词，再运行check_copy核本轮doc.md。不得仅改参照文本来消除漏字告警。

## 按产物适配：原文为准，印给读者的才进册子

用户给的 PPT / Word 是内容的权威，事实与措辞以它为准；但原稿是为 Word 或幻灯片写的，不是为册子写的。“一句不差搬进来”会把不该印的东西也印出去。默认按三类处理：

| 原稿里的东西 | 册子里怎么办 | 怎么记 |
|---|---|---|
| 事实与措辞：数字、名称、时间地点、承诺、限定条件、正文句子 | 照原文，一个字不改 | 不用记 |
| 编号 / 标签脚手架：「亮点一：高端品质」「特色2：」「Highlight 03」 | 只留后面的标题；序号要当设计元素（大号 03）时才留 | `adapt.yaml` 的 `strip` |
| 不是写给读者的：备注、批注、给设计的指示（「此处插图」）、版本 / 修订记录 | 不印 | `adapt.yaml` 的 `omit` |

**不去**：读者要照着用的序号（任务册、指南里的「步骤一」、Day 3、第三天、任务 A）；「标签：值」（时间：9:00、地点：、费用：，标签本身就是信息）；联系方式、限定条件、免责说明。拿不准就留着，写进第 1 轮确认单问用户。

流程：

1. `plan.py` 在 plan.md「需要用户确认的原文问题」里报候选：【编号标签前缀】【疑似非读者内容】【标题带版本标记】。只报不改，也报不全，通读原文时自己补。
2. 按用途（purposes/ 与 brief.md）判断，在项目根目录写 `adapt.yaml`：

```yaml
strip:    # 去标签前缀：只去掉匹配的部分，保留后面的内容
  - match: '^(亮点|特色)[一二三四五六七八九十\d]+[：:]\s*'
    why: 宣传册里编号没意义，只留冒号后的标题
omit:     # 整行不进册子：text 是行首文字（忽略标点空格，至少 4 个字）；或用 match 写行首正则
  - text: '备注：此页最终稿待校长确认'
    why: 文档内部备注
```

`match` 是正则，匹配到的部分被去掉：前缀用 `^` 开头，标题末尾的版本标记（「（终稿v3）」）用 `$` 结尾；行首的列表符号、`#`、粗体标记已先忽略，去掉后整行为空的不剥。`book.yaml` 里照剥完的写：title 写「高端品质」，不要再写「亮点一：」。
3. `check_copy.py` 认账：声明过的不算 MISSING，写出 `.qa/adapt-report.md`。声明没命中任何一行、或成品里还印着声明要去掉的内容 → `ADAPT WARN`（doctor 作提示）；声明写错 → `ADAPT ERROR`（doctor 硬伤）。
4. 交付时把适配报告列给用户（去了哪些前缀、省了哪些行）；用户要放回，删掉 adapt.yaml 里对应条目，重新构建。

边界：`adapt.yaml` 只管“剥前缀”和“整行不印”。改措辞、拆合句子仍是改写，要授权，记 copy-changes.md；不能用 omit 去消真正的缺字，只有确认不是给读者看的才省。美化路线（`book.frozen: true`）文字冻结，不许有 `adapt.yaml`，doctor 会拦。

## 适配顺序

1. 先按editorial-advisor.md审完整输入并处理逐页建议，再编写下述page-plan.md，给内容标明角色，定采用文案和设计方案。未做这一步，不先填模板再凭溢出结果补救。
2. 选择语义块：统计用stats/kv；时间地点分别成段或条目；“标签＋数值”“数字＋单位”作为信息组；多个短句不能只因累计字数多就自动分栏。
3. 确定阅读路径：短导语与短说明保持完整块（flow: keep）；长正文才考虑自动或明确分栏。多个并列模块用显式cols，每栏放完整信息组。
4. 构建测实际字体后的换行。正文用pretty优化自然断行；标题按既有层级处理。先调整分组、栏宽与版式，再在授权范围内改写；容量仍不足则拆页。
5. 检查实际PDF：不能留下句子后半截独自作为栏首、数字与标签失联、分隔符悬在行首、日期地点和时长挤成断续字符串。普通长文正常转栏按阅读任务判断，不能机械禁止所有跨栏续读。

## 读懂内容：给每组文案做内容画像

在 copy_map.md 的每组旁边写 4 个判断，再决定用什么块、放第几页：

| 判断 | 问自己 | 例子 |
|---|---|---|
| 角色 | 这组在全书里干什么：开篇 / 建立信任 / 讲理由 / 讲亮点 / 讲细节 / 让人行动 / 让人书写 | “往届营地回顾……” = 建立信任 |
| 形态 | 它天然是什么形状：一句金句 / 一段叙述 / 并列清单 / 数据 / 时间流程 / 对照 / 表单 / 联系方式 | “40 所学校 / 3000+ 营员” = 数据 |
| 分量 | 多少字；最重要的是哪一句 | 120 词正文 + 1 句金句 |
| 画面 | 它让人想到什么画面；原文有没有对应的图 | “星空观测夜话” → 星空、望远镜 |

**形态决定内容块**（不是版式决定内容）：

| 形态 | 首选 | 不要 |
|---|---|---|
| 金句、口号 | `display` 大字，或 `quote`；有照片时压在照片的安静区 | 埋进正文段落 |
| 叙述 | `p` / `letter`，按行宽规则排（layouts.md §0） | 拆成假清单 |
| 并列 3–6 项 | `items`（`style: big` 编号）、`cards`，或 `cols` 并排 | 每项配一个图标、一张小图 |
| 数据 | `stats` 大数字，“标签 + 数值”成组 | 埋在句子里 |
| 时间 / 日程 | `kv`（时刻 → 事项）、`timeline`、`sheet` | 写成段落 |
| 对照、多属性 | `sheet`（已填）、`cols` | 长段落 |
| 任务、书写 | `step` + `write`，按任务定制：画图用 `box`、对比用 `table`、选择用 `choice` | 统一几条横线 |
| 联系、报名 | 封底 `kv` + `qr` | 放在正文中间 |

## 先定整册节奏，再写逐页方案

page-plan.md开头先列整本的翻页节奏：章节转换、视觉锚点、跨页位置/任务、密集与呼吸页。不能只有28张独立页面清单。整册字体分工同时记录，西文标题/正文/标签/装饰字的选择与试排见style.md §2.4。

像剪片子一样排节奏：高点（封面、章节开篇、最打动人的亮点、结尾号召）用海报页或跨页，细则、费用、表格用纸面页；“大图（呼吸）→ 信息（阅读）→ 大图”交替，连续 3 页纸面为主就插一页海报或跨页。配图先给高点页：最好的照片留给高潮，横图给跨页，竖图给海报 / 侧条，一图一用；图不够或不对题时记下来，问用户补图或 AI 补图。内容少就给高点更多空间，不加原文没有的内容凑页。

对16页以上有图片的宣传册，明确采用几组跨页及理由；未使用跨页时写明素材/内容/交付约束。用户要求恢宏跨页时，须产出实际SPREAD_*联合构图，不能把两张独立单页并排称为跨页。左右须偶数页起，主图/色面/网格或标题关系真正贯通，并分别检查中缝、主体与文字。原文页数与内容约束由整册统筹，不能为了每页不同而拆散同一时间轴。

合页/拆页后重新核对整册：可见章号、完整章序、目录目标、PDF书签、跨页单双页、封面封底和装订总页数。合并章扉与概览不等于删除章节识别；不能只把本页排好，再把不合装订的页数留给交付说明（章节写法见blocks.md，装订约束见delivery.md）。

修订时先写明反馈的影响范围：内容分组问题检查同类信息，系列样式问题检查全部成员及续页，图片/品牌图形问题检查共用组件及所有使用页；字体、纸面或页序改变时重新检查整册。逐项标记采用稿、page-plan、book.yaml与成品是否已同步；无关已认可页保持不动。用户未点名的连带页不是重新征求同一授权的理由。

## 必经产物：page-plan.md

放在项目根目录（new_project.sh 会生成骨架），覆盖全部拟排页面。开头一张页面总表：页 / 文案（copy_map.md 的 S 编号）/ job / 视觉主角 / 版式 / 图——一眼看全整册，lint.py 也按它查哪几页还没设计；下面每页（跨页写成“第 4–5 页”）一节，写下列各项。改版时先更新受反馈影响的页及同类页。独立图版也写清任务与保留的图内文案。原文、方案、book.yaml、实际PDF之间应能逐项追溯。

每页至少写：

- 页面任务：读者看完要知道或做什么；本页只设一个主要焦点。
- 文案分工：主标题、栏目/装饰字、序号、导语、正文、并列条目、数据、时间地点、行动信息；没有的项明确不设，不为凑结构编字。
- 采用文案：实际要排的内容；有改写列原句→采用句与保留的信息点，不能只写“后面精简”。
- 展示方案：主图/图组、索引或数字的画法、信息分组、文图比例、阅读顺序与页间关系。先用文字说明设计意图，再选引擎现有块；不能用“PAPER/TWO”代替设计方案。
- 视觉主角与视线：照片、大字还是数据——一页只有一个主角，其余让位；读者第一眼、第二眼、第三眼看哪（层级不超过 3 级，相邻两级字号至少差一档）。
- 图文关系：字放在照片的哪块安静区（天空、水面、虚化背景、纸面），主体（人脸、建筑尖顶）不被压住 → 用 `focus` / `target` 移主体，用 `split` / 版式控制纸面比例。版式由主角、视线和图文关系推出来：主角是要震撼的照片 → POSTER / SPREAD_P；照片 + 中等阅读量 → T / B；长文字、长清单 → SL / SR；一张图 + 一组要点 → HOLE；章节开篇 + 正文 → SPREAD_OPENER；场景大、两页信息 → SPREAD_H；没有照片的页从 8 种内容版式里按形态选。
- 留白与对齐：内容少宁可留白，不硬撑满；所有块对齐同一组栏线；一页最多 2 种字体家族。
- 验收重点：本页最容易错的事实、语义关系和断行；标注原稿出处。构建后回填实际效果与调整原因。
- 同系列/跨页关系：同一组日程、步骤、名录或统计须一起设计。D1–D5是一条连续时间轴，分页后日期、节点、字体、栏宽和层级保持一致；版式变化不能打断语义。先联合检查相邻页，再检查各页。
- 编辑建议落实：对应editorial-advice.md的具体建议；明确本页相对相邻页的新价值。系列另列完整成员、详情与延续页，不能以单页方案代替整组设计。
- 可选品牌图形延展：启用时按style.md §7.1记录本页/面对页的源形特征、构图与内容联系；未用的页保持净页，不为凑数配暗纹。

角色判定：

| 角色 | 作用 | 设计处理 |
|---|---|---|
| 主标题 | 告诉读者本页讲什么 | 一页一个主要标题，保留可识别的主题/活动名称 |
| 栏目字/装饰字 | 提供语气、系列识别、导航 | Highlight、Chapter、Programme等按上下文判断，不能见到英文大字就当标题；可转为小眉题、边标或图形节奏 |
| 序号 | 标识章/系列项 | 03与Highlight可以分开设计；大号索引、行首编号或系列位置。避免与页码/章号混淆，不凭装饰新增数值 |
| 时间地点 | 回答何时何地 | 日期、城市、时长分别分组，保持标签/值关系，不用一串分隔符凑“副标题” |
| 数据 | 提供可比较的事实 | 学校/人数/委员会/奖项分成独立数据组；不要当连续长句 |
| 导语/正文 | 建立理解、展开内容 | 完整语义优先，结合阅读栏和pretty；长句可在授权范围内编辑 |
| 行动/联系方式 | 告诉读者下一步及通过哪个渠道完成 | 报名动作、索取材料与Email/微信分别成组；渠道标签和地址/账号配对。二维码有明确用途，邮箱/账号不挤成断续长句 |

装饰字是视觉角色，不等于可任意删改，也不等于必须标记data-deco。原稿提供的栏目词、序号和事实仍应核对；引擎的data-deco只服务允许新增元素的原文检查。优先改变呈现层级，需要删改原文字时按授权与文案对照执行。

例如某活动详情页：主标题=海岸潮间带考察；栏目字=Highlight；系列序号=03；生态走廊背景是主题导语；上午采样/下午测绘路线是事实正文。设计时可用小眉题HIGHLIGHT、大号强调色03配主标题、通栏照片，再排导语与路线；不能把“Highlight 03”与活动名同字号堆成两行主标题。

## 引擎做不到时

改引擎去配合设计，不为了套版式牺牲设计：单个特殊元素用 `{html: …}`（只放可信内容）；同一类需求反复出现 → 在 flow.py / canon.py 里加块或参数（见 `dev/maintenance.md`），并在 blocks.md 登记。不在 page-plan 里把设计降级成“能排出来的样子”而不说明。

## 典型正反例

- **“往届回顾”跨页**：一句话 = 我们办过，而且办得好。主角 = 现场主图（真实感）+ 4 个数字（可信度）。视线：左页主图与标题 → 右页标题 → 叙述 → 数字。图文：主图信息丰富时，标题放在底部压暗区，右页文字落在纸面。版式：SPREAD_OPENER（right_layout: SL），数字用 `stats`。
- **Day 3 生态观测任务页**：一句话 = 今天你是现场观察员。主角 = 保护站横图。视线：Day 3 大字 → 行程 → 任务 A。版式：SPREAD_H 横贯上半部，下半纸面放观察记录表（`table`）+ 草图框（`box`）——书写区按任务定制，不是统一横线。
- **反例：排得像 PPT**：6 个理由每个配一张小图 + 标题，排满两页 → 主角不明。正确：一张主场景大图做主角，6 个理由用 `cols` 两栏短句排在纸面，金句单独放大。
- **反例：短导语被机械分栏**：目录页或开篇页的一句话短导语被拆成左右两栏，右栏只剩半截从句。正确：导语保持单一阅读块（`flow: keep`），再调整层级和目录容量。
- **反例：统计数据排成带分隔符的长句**：把 `合作学校: 40 / 历届营员: 3000+ / 课题数: 12` 当成普通段落排成一串。正确：拆为独立统计组（`stats` 或 `kv`），日期、地点、时长分别组织。

当前浏览器优化的能力边界与flow参数见 layouts.md §0；审稿见 review.md。不能把pretty或两端对齐称为已解决所有文案适配问题。
