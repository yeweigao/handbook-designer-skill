# 审稿表：GATE PASS 之后逐页看图用

`GATE: PASS` 只说明溢出、重叠、对比度、缺字这些机器能量的东西没问题。下面这张表是机器量不出来的部分。
看 `.qa/review_*.jpg`（双语再看 `.qa/compare_*.jpg`），每页按 H → S → 不要动 的顺序过一遍，把结果写进 `.qa/review.md`（格式见最后）。

## H · 硬伤（有一条就要改，改完重跑）
| # | 看什么 | 怎么判断 |
|---|---|---|
| H1 | 主体被遮挡或裁坏 | 人脸、建筑主体、产品被文字盖住或被图框截断 → 改 focus / 换图框比例 / 换版式；不能只确认图片容器足够大 |
| H2 | 同一张图用了两次 | images.py 会报 `[同图两用]`；封面图在封底再用一次也算 |
| H3 | 跨页左页不是偶数页 | hb.py 报错；手动插页后再查一遍 |
| H4 | 事实和原文不一致 | 日期、电话、价格、人名、数字逐字对 doc.md（check_copy 只查到“有没有”，查不到“改没改一个数字”） |
| H5 | 不该出现的东西 | brief.md“不能出现”那一栏的东西；占位色块 / TODO / 〔〕没清掉；AI 配图占位 |
| H6 | 图片糊 | images.yaml 里 dpi < 150 且要印刷 |
| H7 | 读者找不到关键信息 | 用途方法（purposes/<kind>.yaml）的 review 第一条：如招生简章的对象、学制、费用、截止日期 3 秒内找不到 |
| H8 | 中英两版不对应 | compare 图里同一页一边有图一边没有、一边多出一段 |
| H13 | 拆页后相对引用失效 | 原文的“见下页”“both are on this page”“本页底部”等相对说法，在拆页 / 合页后要改成实际指向（分页语义审稿） |
| H9 | 品牌错误 | logo 变形、颜色不对、用了品牌包 dont 里的说法 |
| H10 | 导出缺图 | 同时检查实际 PDF 与 HTML，主图、第二张图、多图行不能消失；HTML 正常不能代替 PDF 验证 |
| H11 | 主图失去主次 | 主现场照被当作居中小插图，或挤成无法交代主体的横缝 → 按图片角色、可见面积和主体完整性重排；不能靠空的大容器通过 |
| H12 | 文案角色混淆 | 对照page-plan.md：栏目字/系列号被当成主标题，时间地点与正文混排，或装饰抢过主题 → 回到逐页方案重定层级，再落版；原文大字号不能作为标题角色的唯一依据 |
| H13 | 系列或行动路径断裂 | 连续日程分页后日期/轴线/层级不同，或报名动作、邮箱/账号与标签失联 → 联合重排相关页；先检查系列连贯和行动路径，再检查单页 |
| H14 | 整册跨页规划缺失 | 用户要求跨页却仍是独立单页清单，或仅把两个页面并排展示 → 回到整册节奏方案，做实际联合构图并核中缝/主体；有跨页组件不代表已采用跨页设计 |
| H15 | 编辑建议未落实 | 对照editorial-advice：信息仍挤成带原稿分隔符的正文串；概览/章扉没有独立任务；系列只改一页；截止日期/服务被编号为步骤 → 回到采用文案和系列矩阵，整组修正并复核（editorial-advisor.md） |

## S · 软问题（记下来，一次和用户说；用户没提就不必全改）
| # | 看什么 |
|---|---|
| S1 | 节奏：连续几页都是同一种密度（lint.py 的节奏条 ■▤□ 要有起伏） |
| S2 | 封面钩子：一眼能看出“这本给谁、他能得到什么”吗（purposes 的 hook） |
| S3 | 结尾动作：最后两页有没有明确的下一步（报名、扫码、联系谁） |
| S4 | 每页一个重点：job: 写的那件事是不是这一页最显眼的东西 |
| S5 | 用色比例：看 run.sh 的“用色比例”一行和 `[颜色过重]`；也查连续无图页是否因默认mono都变白/浅灰、失去纸面节奏，按style.md §8安排主题色/深墨页；白字/黑字须通过对比检查 |
| S6 | 大标题长短：中文 ≤ 12 字、英文 ≤ 5 词时最好看；太长的被自动缩小了 |
| S7 | 照片质量参差：双色调能统一一部分，实在差的建议用户补图 |
| S8 | 留白：`[留白]` 提示的页在宣传册里显得空 |
| S9 | 英文版断行：标题在奇怪的地方断开（加 `<br>` 或换词） |
| S10 | 页眉页脚：书名太长被截、页码和目录对不上 |
| S11 | 被自动让过的页：构建时报 `[书写线收紧]`（书写线少了）、`[字号收紧]`（导语、小标签小了一档）的页，插图也可能被缩矮——任务册的书写空间不够就拆页 |
| S12 | 网格：用 `book.html#grid` 打开能看到 6 栏和行线，文字、图片、色块的边都应该落在线上；不在线上的多半是 `{html}` 块 |
| S13 | 图文比例与留白：整页缩到 A4 大小看，页标题、条目标题、正文应形成可读层级；右半页持续空白、正文挤在一角、短句之间隔成条带时重排信息组，不能用放大标题或通栏长句填空 |
| S14 | 阅读行长：连续正文和说明优先阅读栏，检查换行回视是否过远；标题、短图注可通栏。分栏后不能把报名条件、联系方式等短信息拆成两个栏尾；不要把字号变小当作控制行长 |
| S15 | 段落排版：区分连续正文、短信息和强制换行；检查参差的行尾、词间大洞、白河、连续断词及孤行。不能仅用两端对齐开关代替断行与词距优化 |
| S16 | 字体分工：对照整册字体方案，实际西文正文是否符合气质、字面是否过小、灰度/行距是否合适；装饰字、标题、标签不能只因默认同族而失去层级。换字后查密集页与联系方式，字体加载成功不等于排印合格（style.md §2.4） |

用户明确要求修正构图、字号或留白时，相关 S 项也是本轮必须修完的验收项。对重复发生的问题先检查共用版式规则，再处理页面内容分组，不把逐页坐标补丁当作引擎修复。

## 艺术总监式复看（看 review 图时每页问一遍）
- 3 秒内能说出这页讲什么吗？主角是不是一眼可见？有没有两个元素在抢？
- 层级是否最多 3 级？字有没有压在照片主体上？
- 留白是否均衡（一块挤、一块空）？对齐线是否统一？
- 跨页的两页像不像一幅画，而不是两页拼在一起？和前后页比，节奏有没有变化？
发现问题 → 先回 page-plan.md 改这一页（和同系列页）的设计决定，再改 book.yaml，不在 yaml 里直接打补丁。

## 不要动
- 原文的措辞、顺序（用户没让改就不改；美化模式 `book.frozen: true` 一个字都不动）
- 用户在 brief.md 里确认过的风格、配色、页数——要改先问
- 用户在线编辑页里改过的文字（已经写回 book.yaml 的那些，在 `.qa/edits_applied.json`）
- 已经通过的页：只为“更好看”大改已认可的页，会引出新的问题

## 记录格式 `.qa/review.md`

```
# 审稿 〔日期〕 〔第几轮〕
| 页 | 结论 | 问题 | 改法 |
|---|---|---|---|
| 1 | ✓ | | |

| 9 | S6 | 英文标题 9 个词，缩得很小 | 问用户能否缩短 |
```

## 页数多时：分给几个子任务并行看
24 页以上，可以把拼版图按 8 页一组分给几个子任务（每个只看自己那组，拿这张表打分，回报“页号 + 条目 + 一句话”），
你汇总去重后再改。子任务只看不改，改动由你统一做，避免两处改同一页。
