# 审稿表：GATE PASS 之后逐页看图用

`GATE: PASS` 只说明溢出、重叠、对比度、缺字这些机器能量的东西没问题。下面这张表是机器量不出来的部分。
看 `.qa/review_*.jpg`（双语再看 `.qa/compare_*.jpg`），每页按 H → S → 不要动 的顺序过一遍，把结果写进 `.qa/review.md`（格式见最后）。

## H · 硬伤（有一条就要改，改完重跑）
| # | 看什么 | 怎么判断 |
|---|---|---|
| H1 | 主体被字压住 | 人脸、建筑主体、产品被标题或色块盖住 → 改 focus / 换镜像 / 换图 |
| H2 | 同一张图用了两次 | images.py 会报 `[同图两用]`；封面图在封底再用一次也算 |
| H3 | 跨页左页不是偶数页 | hb.py 报错；手动插页后再查一遍 |
| H4 | 事实和原文不一致 | 日期、电话、价格、人名、数字逐字对 doc.md（check_copy 只查到“有没有”，查不到“改没改一个数字”） |
| H5 | 不该出现的东西 | brief.md“不能出现”那一栏的东西；占位色块 / TODO / 〔〕没清掉；AI 配图占位 |
| H6 | 图片糊 | images.yaml 里 dpi < 150 且要印刷 |
| H7 | 读者找不到关键信息 | 用途方法（purposes/<kind>.yaml）的 review 第一条：如招生简章的对象、学制、费用、截止日期 3 秒内找不到 |
| H8 | 中英两版不对应 | compare 图里同一页一边有图一边没有、一边多出一段 |
| H9 | 品牌错误 | logo 变形、颜色不对、用了品牌包 dont 里的说法 |

## S · 软问题（记下来，一次和用户说；用户没提就不必全改）
| # | 看什么 |
|---|---|
| S1 | 节奏：连续几页都是同一种密度（lint.py 的节奏条 ■▤□ 要有起伏） |
| S2 | 封面钩子：一眼能看出“这本给谁、他能得到什么”吗（purposes 的 hook） |
| S3 | 结尾动作：最后两页有没有明确的下一步（报名、扫码、联系谁） |
| S4 | 每页一个重点：job: 写的那件事是不是这一页最显眼的东西 |
| S5 | 用色比例：看 run.sh 的“用色比例”一行和 `[颜色过重]`（60-30-10）；彩色块上的字只能是白或正文色，彩字写在彩块上发虚就是问题 |
| S6 | 大标题长短：中文 ≤ 12 字、英文 ≤ 5 词时最好看；太长的被自动缩小了 |
| S7 | 照片质量参差：双色调能统一一部分，实在差的建议用户补图 |
| S8 | 留白：`[留白]` 提示的页在宣传册里显得空 |
| S9 | 英文版断行：标题在奇怪的地方断开（加 `<br>` 或换词） |
| S10 | 页眉页脚：书名太长被截、页码和目录对不上 |
| S11 | 被自动让过的页：构建时报 `[书写线收紧]`（书写线少了）、`[字号收紧]`（导语、小标签小了一档）的页，插图也可能被缩矮——任务册的书写空间不够就拆页 |
| S12 | 网格：用 `book.html#grid` 打开能看到 6 栏和行线，文字、图片、色块的边都应该落在线上；不在线上的多半是 `{html}` 块 |

## 不要动
- 原文的措辞、顺序（用户没让改就不改；美化模式 `book.frozen: true` 一个字都不动）
- 用户在 brief.md 里确认过的风格、配色、页数——要改先问
- 用户在线编辑页里改过的文字（已经写回 book.yaml 的那些，在 `.qa/edits_applied.json`）
- 已经通过的页：只为“更好看”大改已认可的页，会引出新的问题

## 记录格式 `.qa/review.md`
```
# 审稿 〔日期〕 〔第几轮〕
| 页 | 结论 | 问题 | 改法 |
|---|---|---|---|
| 1 | ✓ | | |
| 5 | H1 | 学生的脸被标题压住 | focus: [.5, .3] |
| 9 | S6 | 英文标题 9 个词，缩得很小 | 问用户能否缩短 |
```

## 页数多时：分给几个子任务并行看
24 页以上，可以把拼版图按 8 页一组分给几个子任务（每个只看自己那组，拿这张表打分，回报“页号 + 条目 + 一句话”），
你汇总去重后再改。子任务只看不改，改动由你统一做，避免两处改同一页。
