# 选题调研：只有题目、没有原文（或原文不够）时

适用：“做一本清迈研学手册”“做一本 AI 教育的科普册”，用户没给文字稿，或者给的稿子缺关键信息（开放时间、票价、历史背景）。
原则：**每一个事实都要能追到来源**。调研来的内容写进 `facts.md`，成品里的每个数字都要能在 doc.md 或 facts.md 里找到（`facts.py` 每次构建都查）。

1. 第 1 轮沟通合同照常做（new.md §2），多问一句：“这些内容由我去查公开资料，你来确认，可以吗？哪些地方你们有内部资料？”
2. 查资料：WebSearch / WebFetch 优先官方来源（场馆官网、政府 / 学校网站、权威百科），其次大媒体；论坛、自媒体只作线索。时效性强的（价格、开放时间、政策）注明访问日期。
3. 写 `$P/facts.md`，每条一行：
   ```
   - 双龙寺海拔 1073 米，建于 1383 年 —— 清迈旅游局官网 https://… （2026-10-17 访问）
   ```
4. 用 facts.md 写 `$P/doc.md`（这本书的“原文”）：按 purposes/<kind>.yaml 的页面角色组织，句子尽量短，事实句和 facts.md 一一对应；你写的过渡句、介绍句要少，并在交付时说明哪些是你写的。
5. 把 doc.md 发给用户确认（这一步替代“用户给原文”）。确认后照 new.md §3 起走。
6. `run.sh` 里的 `facts.py` 会列出 `[无出处数字]`：成品里有、但 doc.md / facts.md 里都没有的数字——要么补出处，要么删。
7. 交付时：附 facts.md（来源清单），提醒出发前 / 印刷前按官方渠道复核时效性信息。

图片：用户没给照片时，优先用有明确授权的图（官方新闻图库、CC 授权），在 `images.yaml` 的 source / license 写清；AI 配图见 `references/images.md`。
