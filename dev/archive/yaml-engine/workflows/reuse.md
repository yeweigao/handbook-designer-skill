# 路线 reuse：沿用旧册（同一套外观和页序，换新内容）

适用：“今年的招生简章照去年那本做”“第二期营地手册和第一期一样的样子”。外观、版式、页序已经被认可过，只换文字和照片。

```bash
bash $HB/new_project.sh $P 今年原文.docx 今年照片/ --from <去年的项目目录>
```
→ 新 book.yaml：去年的 `book:` 设置（风格、配色、品牌包、字体、语言）+ 去年的页序骨架（版式、job、surface 保留；文字全部换成 `TODO`；照片文件名保留、旧照片复制过来）；
去年的 book.yaml 另存为 `book.prev.yaml` 对照；去年的 brief.md 复制过来（route: reuse）。

1. 沟通合同只确认“有什么变了”：读者、动作、必须出现的东西今年有没有变。外观不再出方向样张（除非用户要换）。
2. 按今年的 doc.md 把 `TODO` 填掉。今年多出来的内容加页（同版式，引擎自动换镜像），少了的页删掉——删 / 加页时注意跨页的奇偶。
3. 旧照片：今年有新照片就换；沿用的旧照片在交付时列出来，让用户确认还能用（人物、场地是否变了）。
4. `lint.py` 会列出没填完的 `TODO`；`run.sh` → 导出 → `workflows/visual-review.md`逐页审改/重导复核，检查新文案与新照片是否仍适配旧版式。
