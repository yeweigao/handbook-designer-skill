日期：2026-10-21。状态：**计划已落盘；四页独立 demo 已完成；正式 Skill 与引擎改造尚未开始。**

本文是本轮架构改造的权威计划，供后续 agent 接手。用户当前要求只写计划，不在本次继续实施。后续收到执行指令时，以本文的一致终态为目标组织工作；下面按职责列出工作包与依赖，不拆成分期上线，也不建立新旧双轨。

本文取代 [STRUCTURE-FREEDOM](STRUCTURE-FREEDOM-2026-10-21.md) 中的 COMPOSE YAML 路线、强制发牌与多轮确认、普遍固定网格和以结构差异为主的验收。[IDEAL-FORM](IDEAL-FORM.md) 的「有判断、能测量、会学习」继续成立；与本文冲突的具体机制以本文为准。[ROADMAP](ROADMAP.md) 和 [TODO](TODO.md) 保留为历史缺陷与回归证据，不再决定本轮目标架构。

## 最重要的结果

**稳定产出有表现力、阅读舒适、可可靠交付的成品，是第一目标。** LLM 自由度、代码简化、通过门禁都服务于这个结果。HTML/CSS 提高表达上限，但不会自动提供审美下限；下限来自好的参考作品、明确的物理约束、真实成品审稿与跨任务评测。

完成后的 Skill 应当像一位能独立做判断的出版设计师：理解材料，提出适合这本书的视觉主张，直接创作页面，检查真实输出，主动修订，并留下可验证、可迁移的经验。它不需要先从布局枚举中选择，才能获得创作资格。

### 已确定的产品决定

- **HTML/CSS/SVG 为唯一页面作者源。** 不做 YAML 自由组合 DSL，不实现 YAML 兼容，不保留双向转换。
- **品牌基因用 CSS 表达。** 固定一册或同一系列的颜色、字体角色、字号层级、线条、间距与图像语言；页面构图交给模型。
- **六栏、28px 基线和现有字号档是现有家族的默认基因。** 它们不是所有作品的普遍物理定律。可选择适合内容的新家族，但不能逐页随意漂移。
- **低层原语和优秀示例提供参照。** 不把整页封面、双栏、卡片等封装成必须选择的模板菜单；也不禁止作者使用普通 Grid、Flex、定位或页面专属 CSS。
- **没有固定的多轮用户确认仪式。** 继承已给出的授权与品牌约束；只有缺失信息会实质改变内容、方向或交付时才问。代表页试作与内部审稿由 agent 自主完成。
- **不要求每本都不同。** 系列一致性和内容适配优先。探索任务可以比较不同方向，日常任务不强制抽签、凑三版或避开上一本结构。
- **经验自动收集，晋升依证据。** 单次成功不是通用规则；重复两次只足以成为候选，不能直接改变默认行为。
- **不兼容旧接口，但保留必要能力。** 内容保真、多语言、图片来源、装订、源文件交付和编辑回写不能因换架构而消失。
- **多语言共用一份作者源。** 页面结构只写一次；各语言文案按稳定内容 ID 注入，语言间的长度与断行差异用该语言的覆盖 CSS 处理。不为每种语言各写一本 HTML，避免改两遍和版本漂移。这是内容替换，不是布局 DSL。
- **印刷可读性有硬下限。** 正文、关键功能信息、辅助文字的最小字号与对比度属于物理约束：家族 CSS 给出默认值，QA 作为硬项检查，不随自由构图下调。

## 目标架构与责任边界

| 层 | 负责 | 不应承担 |
|---|---|---|
| 材料与意图 | 原文、事实、图片、读者、阅读任务、品牌约束 | 预先替每种内容指定一种页面模板 |
| CSS 基因 | 色彩与排印体系、低层原语、家族共同语言 | 决定每页放什么、如何开场、整册节奏 |
| 作者源 | 模型直接写 HTML/CSS/SVG，安排结构、构图与页序 | 为满足引擎枚举而改写材料 |
| 渲染与测量 | 固定环境、资源就绪、物理页面、内容与几何检查、导出 | 悄悄缩字、收间距、删书写线、重裁图片 |
| 视觉审稿 | 阅读体验、照片主体、整册节奏、最弱页、真实 PDF | 把通过技术检查等同于设计优秀 |
| 经验层 | 记录有效选择与失败、检索参考、验证后晋升 | 仅按出现次数积累越来越多的强制规则 |

### 项目文件契约

以下是目标目录约定，尚未实现。可以在实现前统一调整命名，但不得改变各文件的责任，也不得再造布局 DSL。

```text
project/
  project.json             # 入口、语言、物理页、装订、资源与渲染配置
  brief.md                 # 已有授权、阅读任务、重要假设；保持简短
  page-plan.md             # 页面任务与整册节奏，必要时含设计主张
  book.html                # 可直接编辑的页面作者源（各语言共用页面结构）
  design.css               # 本项目冻结的家族基因与低层原语
  book.css                 # 本书专属构图与有理由的局部变化
  copy/<lang>.json         # 各语言文案表，按内容 ID 注入 book.html 并转义
  lang/<lang>.css          # 可选：某语言的长度、断行、字重与页面覆盖
  print.css                # 由物理页配置生成；只含打印尺寸与边界，不排内容
  assets/                  # 实际使用的字体、照片、SVG 等本地文件
  sources/                 # 原始材料、来源清单、稳定内容 ID 与映射
  experience.md            # 本项目观察、修订原因与证据链接
  .qa/                     # 检查、指纹、PDF 栅格、审稿、失败记录
  out/                     # 最终 PDF、预览、离线 HTML、可重建源包
```

- `project.json` 只描述项目和生产参数，不出现 `layout`、`cells`、`span`、内容块树等排版语言。多语言通过语言列表、各语言文案表和可选覆盖 CSS 表示，共用同一份 `book.html`；每种语言独立渲染、独立验收。
- 物理尺寸、出血和装订配置只维护一份；`print.css` 从它确定性生成，设计 CSS 消费对应变量。重复声明或冲突应报错，不能由加载顺序决定纸张大小。
- `design.css` 是该项目视觉 token 的权威源。仓库中的家族文件是创建项目的来源；项目复制后记录版本与哈希，不跟随仓库更新而静默换样。
- `book.html` 与 `book.css` 是作者源，PDF、截图、离线嵌入版不是回写来源。不可每次 render 都用生成器覆盖作者源。
- 内容 ID、页面 ID、DOM ID 分开：内容跨页仍能追溯同一原文；页面重排不改变身份；同一内容多处引用须显式登记。

### 最小作者约定

```html
<section class="page" data-page-id="p-cover" lang="zh-CN">
  <h1 data-source-id="title" data-edit-id="cover-title">原文标题</h1>
  <p data-source-id="intro-01" data-edit-id="cover-intro">原文导语</p>
</section>
```

多语言时，元素内的文字是默认语言文案；构建按 `data-source-id` 从 `copy/<lang>.json` 注入其他语言（按文本转义）。缺译、多余译文、ID 不匹配都报错。若某语言因长度必须改变分页，在 `lang/<lang>.css` 或显式的语言页面覆盖中处理并记录原因，不复制整本。

每个 `.page` 对应一张输出物理页；实际页数以 PDF 验证。源内容默认是转义文本，只有受信的作者代码才能构造 HTML/SVG。不要要求给每个装饰元素填元数据：仅内容追溯、编辑节点、页面与确有必要的裁切/叠放说明需要标记。

## CSS 基因与作品质量

### 家族 CSS 应包含什么

- 颜色角色：纸、正文、标题、强调、次要文字、分隔线和反白；明确角色组合与可读性。
- 字体角色与真实文件：中西文标题、正文、标签、数字；实际字重、斜体和字符覆盖。
- 正文与展示字的字号层级、行距、阅读行长、段间关系。小字可用于辅助信息，关键事实不能为了装下而降为小字。
- 印刷可读性下限（项目可提高，不可静默降低）：A4 正文 ≥ 14px（10.5pt），常规阅读册默认 16px（12pt）；日期、地点、联系方式、步骤、表格数值等关键功能信息 ≥ 12px（9pt）；眉标、页码、图注等辅助文字 ≥ 10px（7.5pt）；正文与关键信息对比度 ≥ 4.5:1。其他画布按物理尺寸换算。降低下限须有用户明确授权并记入 brief。
- 参考网格、基线和间距级数、线宽、图注与图像处理语言；Campus 先继承现有六栏/28px/配色，建立清楚的默认值。
- 低层原语，例如文字栈、引文、规则线、图注、图框、填写线、标注、对齐工具。原语数量按实际需要决定，不凑固定数量。
- 打印安全变量的消费方式与调试网格。调试层不可进入最终交付。

页面作者可以用原生 CSS 构图，允许专属类与必要的局部尺寸。默认遵循家族档位，但不把「不许裸 px」「必须吸到六栏」改写成新的禁令。整册的层级、线条与色彩角色必须自洽；改变家族级决定时记录原因并复查全册。

### 不让 CSS 重新变成模板菜单

- 共享层不收纳整页 `.cover-layout-01`、`.two-column-page` 等只能套用的结构。
- 完整页面与跨页作为可阅读、可拆解的示例存在，不成为渲染器的注册项。
- `book.css` 可以定义本书的封面或对照页；只有在不同内容上反复证明可迁移的低层规律才上升到家族层。
- 不以 DOM 类名、布局名称、空白比例或相邻页相似度判断优秀与否。疏朗、重复、密集都可以是有效意图，必须看阅读任务是否兑现。

### 必须补足的视觉参考资产

审计现有 `dev/gallery`、样册与风格定义，区分真正不同的排印/摄影语言和仅换颜色的变体；不要沿用文档里互相冲突的风格数量。每个保留的推荐家族，至少有真实材料驱动的开场、连续正文、密集信息与跨页示例，并有实际 PDF 与源文件。

每个示例解释少量关键决定：什么材料适合它、读者先看什么、哪里不能照搬。反例保留失败图、材料条件与修订结果。短文案导致某个 demo 失败，不应晋升成「短文案永远不能用阅读式页面」这样的普遍禁令。

照片示例必须使用与主题相关、来源和使用条件明确的真实照片，检查人物、主体、方向、裁切和图文关系。合成色带可用于几何回归，不能替代摄影艺术指导评测。纯文字项目可以用排印与语义矢量图形成表现力，不为“酷炫”加入无关装饰或假数据。

## 确定的渲染与打印契约

### 运行时与资源

- 保留已有 Node/Playwright 基础，锁定依赖版本、Chromium revision、字体文件和渲染参数。正式验收禁止静默回退到系统 Chrome；环境不满足就给出可操作错误。
- 资源准备与正式构建分开。允许准备时获取需要的字体或图片，但进入正式 render 前必须本地化、记录来源并固定文件哈希；不允许边渲染边下载、下一次构建自动替换字体。
- 等待字体加载、图片解码、SVG 依赖和作者资源全部就绪；设置明确超时。`document.fonts.ready` 或固定睡眠不能单独证明资源完整。
- 主动拒绝外部资源请求。支持的本地加载方式固定并记录；打印页不依赖第三方脚本、时间、随机数、动画、用户滚动或设备字体。
- 默认静态作者页面；编辑器脚本与交付打印隔离。确需预处理的图形在 render 前生成稳定 SVG/图片，不引入另一个页面布局生成器。
- 同一份 print media、页面数据和资源快照用于 QA 与导出。屏幕端只调整书页的呈现与缩放，不改页面内部排版。

### 页、出血与装订

- A4 的成品尺寸是 210×297mm；用物理单位与 PDF box 检查，不能只检查截图 794×1123。其他画布通过同一契约声明，不在检查器写死 A4。
- 区分成品框、出血、PDF 媒体框和安全区。无出血时成品框等于媒体框；有出血时 `.page` 表示包含出血的物理输出页，成品框为内缩区域。必要的 PDF TrimBox/BleedBox 后处理必须进入最终指纹与 postflight。
- 正文与功能信息遵守安全区，装饰/满版图片可进入出血；`overflow:hidden` 不是通过裁切检查的理由。
- 单页顺序、阅读跨页、封面和空白页明确建模。只有所选装订方式要求时才检查四的倍数，不能为了门禁擅自插入空白页。
- 跨页用两张有稳定配对 ID 的物理页，共享可追溯的图像裁切坐标；核对偶数左页、奇数右页、中缝连续性和中缝安全。不要以一张双宽截图冒充两张 PDF 页验收。
- 不把浏览器 RGB PDF 宣称为已满足任意印厂 PDF/X、CMYK 或拼版要求；按项目声明的交付规格验证。超出受支持规格的要求必须明确报告。

### 只测量，不暗中改设计

清理 `hb/fill.js` 中自动缩字号、调整字重/行距/间距、减少书写线、改变颜色与图片处理的行为。正式 render 默认只读作者源，不通过隐藏改版把页面塞进去。

测量结果给出页面、内容 ID、位置、超出量与建议。agent 修改作者源后重新构建。若保留显式的适配辅助工具，必须给定边界、记录前后差异、写回可审阅源文件；不能以注入临时样式的方式只修改交付结果。

### 长文与续页

Chromium 不会把文字自动续排到下一张固定页。旧 `flow.py` 承担的续页能力不能随 YAML 一起消失，也不能全靠 agent 反复手工拆段、重建。

- 提供一个确定性的续页辅助工具：输入作者源中标记为可续排的内容流和目标页框，按实际渲染测量，在段落或句子边界拆分，生成续页结构并**写回作者源**，输出拆分前后差异供审阅。它只移动内容，不改字号、行距、间距，也不删内容。
- 拆分默认避开标题孤行、段首/段尾单行、图注与图分离、表格行被切断；做不到时报告具体位置，由 agent 调整构图。
- 拆出的片段保留原 `data-source-id` 并记录片段序号，内容覆盖检查能把跨页片段合并回原文核对。
- 多语言各自拆分；某语言需要多出续页时按语言页面覆盖处理。
- 该工具属于最先统一的契约；24 页以上的密集双语基准必须经由它完成。

## 内容、图片与编辑能力

### 保留内容可信度，重写对 YAML 的依赖

- 将输入提取与排版生成分离。原 PPT、DOCX、Markdown 等材料提取为可读内容、原始定位与素材；不再由 `doc2yaml.py` 先决定页面结构。
- 原文逐片段建立稳定 ID，追踪正常正文、标题、图注、表格、重复引用和跨页拆段。不能只查六句锚点或全文字符串是否存在。
- 明确原文搬运、可润色、可翻译、内容冻结等任务模式。MISSING/ORDER/EXTRA 按实际授权解释；页序可调整不等于原文必须线性原样排放，内容冻结则执行严格对应。
- 装饰标记不豁免正文覆盖；透明字、页外字、裁掉的字和隐藏副本不能算已展示。结合源映射、DOM 可见性、最终 PDF 文本与视觉证据判断。
- 事实和图片来源保存为项目资料。检查依据是实际内容节点和素材引用，不能把 CSS 数字误判为无出处数据。
- 图片检查依据实际显示区域与有效像素，区别 `contain`、`cover`、裁切、SVG、二维码和 logo。来源/授权缺失与低清晰度分别报告，不能因为文件名像 logo 或 AI 图就自动通过。
- 跨页后“见右图”“本页两者”等关系、译文与原文对应、图表数字含义属于语义审稿，不伪装成已由字符串检查证明。

### 编辑回写

在线编辑由独立仓库 `folio-html-studio`（https://folio.25868456.xyz）承担，见下节「与 Folio 联动」；原则如下。

- 在线编辑只开放已标记的内容/图片节点，稳定 `data-edit-id` 映射到作者源；禁止以整页序列化覆盖源文件。
- 回写校验旧值或源指纹，遇到并发修改就报告冲突。保留行内强调、链接与段落结构；用户输入按文本处理，不能成为任意代码。
- 改字、换图、改语言后重新跑受影响检查与最终输出审稿；旧的验收自动失效。
- 普通 PDF、可编辑 PDF（保留为正式交付物）和源文件是不同承诺。不得仅凭“没有 Type 3 字体”宣称任意 PDF 编辑器都能无损修改；明确支持范围并实测文本/图像与普通 PDF 的一致性。

### 与 Folio 联动

分工：Skill 负责作者源、渲染、QA、最终 PDF 与可编辑 PDF；Folio 负责浏览器内的可视化修改。Folio 保持纯本地：文件在用户浏览器里读取和保存，不上传服务器，不需要账号或存储。Folio 的浏览器打印不是正式交付，任何修改都要回到 Skill 重建和验收。

- **导出编辑包**：构建通过后，Skill 导出 Folio 编辑包（zip：渲染好的 HTML、全部本地资源、构建 ID）。HTML 保留 `data-page-id` / `data-source-id` / `data-edit-id`。用户在 Folio 网站导入这个本地文件修改。
- **两种用法**：
  - 只做最后微调、直接使用：用户在 Folio 下载修改后的 HTML 并打印，到此结束，不回 Skill。
  - 修改要进入源文件（之后要出正式 PDF / 可编辑 PDF、同步其他语言、改版或复用）：用户把 Folio 下载的 HTML 交回 agent（聊天附件或放进项目目录）。
- **写回靠对比，不靠替换**：Skill 按构建 ID 找到这份 HTML 所基于的版本，按内容 ID 对比出改动。文字改动写回 `copy/<lang>.json` 或 `book.html`，保留行内强调与链接；换过的图片取出放进 `assets/` 并登记来源；Folio 的覆盖样式（`data-folio-overrides`）转成 `edits.css` 中按 page-id / edit-id 定位的规则，由 agent 审阅后保留或并入 `book.css`。没有 ID 的改动和无法定位的改动列给用户，不猜。下载的 HTML 本身不作为新的作者源，因为它只含一种语言，并嵌入了资源与覆盖层。
- **冲突与重建**：基于的版本已经改过时，逐处核对旧值，对不上就报告。写回后重新渲染、跑全部检查（含可读性下限）、按连带范围做视觉审稿，再导出新的编辑包。
- **Folio 需要的改造（小）**：导入和下载时保留 Skill 的 ID 属性与构建 ID；覆盖样式继续写在可识别的位置；界面显示所基于的构建版本；对没有 ID 的文字修改给出提示（仍可修改）。不新增修改清单导出，也不需要服务器。
- 现有 `edit_page.py`、`editor.js` 与 Artifact 数据库发布流程退役。

## QA、审稿与可交付状态

### 三种状态，避免把未知写成通过

检查报告至少区分 `pass`、`fail`、`unverified`，并附证据和影响范围。强制项缺依赖或未运行必须阻止正式交付，不能像当前 postflight 缺 pypdf 时那样记录为通过。提示项与硬错误分离；流程退出码必须反映真实失败。

### 技术检查

- 支持原生 Grid、Flex、普通流与定位的页面，不依赖旧 `.a`、`.rcp`、`.flow` 等布局类。
- 覆盖文字范围、容器裁切链、页边/安全区、内容溢出、关键内容遮挡、资源缺失、字体实际使用与字符覆盖。字号可加载不等于每个字符有字形；缺字和未声明回退需要专门证据。
- 合法叠放与装饰出血允许存在，声明仅解释局部关系，不成为整页豁免开关。复杂 mask、transform、SVG/filter 等无法可靠自动判定时标为待视觉核验。
- 字号与对比度的可读性下限是硬项，按文字的内容角色（正文 / 关键信息 / 辅助）检查，低于下限即 fail。内容角色由家族原语或少量作者标记确定；未标记的文字按正文要求检查。
- 行长、密度、留白、相似度是诊断信号，不能用统一阈值代替艺术判断；影响正文可读性或功能信息识别的问题仍必须处理。
- 几何检查同时有正例与负例：合法海报叠放不能误报，隐藏正文、溢出后被截断、过度裁掉照片主体不能因盒子合法就放行。

### 最终 PDF 审稿

导出完成后，先检查最终 PDF，再栅格化**这份 PDF**进行整册缩略图、面对面跨页和逐页阅读尺度的审稿。屏幕截图用于调试，不能替代最终成品。

视觉审稿至少回答：

- 这本书有适合其材料和读者的视觉主张吗，还是任意内容都能套进去？
- 入口、主文、辅助信息是否形成清楚的阅读顺序？缩略图看有节奏，正常阅读大小看字是否舒适？
- 正文页、密集页、无图页是否也完成了设计，而不是仅封面漂亮？
- 照片主体、图注关系、连续阅读和跨页中缝是否成立？
- 同册的字体、颜色和线条是否统一，差异是否服务页面任务？
- 最弱的一页是否仍然达到交付标准？任何关键缺陷都不能被平均分掩盖。

审稿分为「不合格 / 可交付 / 优秀」，按页记录具体问题和修改建议。独立 reviewer 先看 brief 与匿名的最终 PDF，不先读作者为设计辩护的文字；之后才核对设计意图与工程报告。作者自评可以存在，但不能替代独立评测。

实际创作中由 agent 自主修订，停止条件是达到质量要求或明确记录受限项，不是写满固定轮数。正式基准评测使用下文固定返工预算，以免通过无限手工打磨掩盖系统问题。

### 审稿必须绑定最终文件

- 输入指纹覆盖 HTML、全部递归 CSS/SVG 依赖、图片、字体、基因、项目参数、检查规则版本与工具版本；不能只哈希 YAML 或 brief。
- 输出记录 PDF 哈希、实际页数、各页栅格哈希、技术报告、视觉报告与来源构建 ID。
- 任一有效输入发生变化，旧验收失效。导出器不得拿旧 `.qa/gate.json` 为新 PDF 背书。
- 任一 PDF 后处理、可编辑版本转换、字体子集化或重新打包导致输出变化，都必须重新核对实际产物。
- 先写入临时构建目录，完成验收后发布最终产物；失败时保留诊断，不把半成品标为最终交付。允许显式生成草稿，但状态必须明确。

## 离线交付与源包

资源打包要处理真实依赖闭包，而不是只用正则替换 `<img src>`。覆盖 HTML 图片及 `srcset`、CSS `url()` / `@import` / `@font-face`、背景图、SVG 外部引用与嵌套样式；遇到不支持的依赖必须报错。

交付至少包含：最终 PDF、逐页预览与拼图、审稿摘要、离线 HTML、可编辑作者源和所有必要本地资源、来源/许可清单、版本与重建命令。源包不得依赖原机器绝对路径、符号链接、私有缓存或仓库 `dev/fonts`。

在新的临时目录解包并关闭网络，验证 HTML 打开、资源完整、重建成功与输出一致性。单文件 HTML 的嵌入方式改变了输入，应针对该产物复查；不能只检查原始项目正常。

## Skill 工作方式与经验进化

### 工作流重写

`SKILL.md` 保持短，职责是目标、授权边界、作者约定、检查/导出入口和文档路由。删除「只选版式，不写尺寸坐标颜色」和必走两轮确认。流程不要求先写完整设计论文；只保留能帮助创作和交接的简短主张与页面任务。

| 工作流 | 改造后的职责 |
|---|---|
| new / quick | 读材料与已有授权，判断内容和视觉方向，自主试作实际关键页与最难页，扩展全册，审稿并交付；quick 不降低成品检查 |
| beautify | 执行约定的内容冻结与页对应，仍允许自主构图；不能把自由发挥当作改写授权 |
| reuse | 默认继承明确要求的品牌或系列基因；结构可延续也可调整，不强制“必须新” |
| revise | 定位反馈到源内容/页面，修改并重新验收受影响范围；基因变化须看全册 |
| brand | 输出实际 CSS 基因、字体/资源与优秀示例；不再把品牌写成布局选择器 |
| research | 补事实与相关素材的来源证据；研究结果服务页面，不凭空填充文案 |
| edit-online | 导出 Folio 编辑包，对比用户交回的 Folio HTML，经稳定 ID 安全回写作者源，处理冲突，重新构建并导出新编辑包 |
| visual-review | 以最终 PDF 的全册、跨页与逐页证据执行审改闭环 |

代表页是 agent 内部的质量控制：优先选择最能检验方向的页面与最难内容；涉及照片/跨页就包括它们。它不是每次要求用户从三个方向选一个的固定关卡。

### 经验从项目证据生长

> 本轮只要求：重要修订按下述字段写入项目 `experience.md`，并有轻量索引。候选验证、晋升与撤回闭环在主体架构通过 DoD 后单独建设和验收。

每次重要修订自动记录：材料条件、失败/成功现象、实际决定、源文件与输出证据、适用边界、反例、质量结果。用户偏好与通用规律分开；不要把“用户这次喜欢深蓝”记成所有项目默认深蓝。

晋升路径是观察 → 候选 → 在未见材料上验证 → 示例或规则。两次出现只能进入候选。验证不能复用同一演示文案，也不能由改规则的同一段上下文给自己评分。

- 经验证的示例可自动进入参考目录，带适用范围、版本和证据。
- 改变默认生成行为、硬门禁或共享基因的规则，需要独立行为评测和回归结果；未经验证不得自动改 `SKILL.md`。
- 检索优先给出少量与当前材料相关的经验，而不是把历史经验全部塞入上下文。
- 保留负例与撤回机制：新证据表明规则伤害表现力或阅读质量时，撤销或缩窄适用范围。
- 不建设大型学习平台。先用仓库内结构化记录、索引和简单检索跑通闭环，证明实际改善产物后再扩展。

### 实施依赖与协作边界

- 最先统一作者源、页面/跨页、资源、内容 ID、多语言注入、续页拆分、可读性下限、审稿记录契约，再由多个 agent 并行处理 CSS/作品、渲染/QA、内容/编辑、文档/评测；这些是依赖关系，不是多阶段产品路线。
- 为各 agent 指定文件所有权。共享 schema、CSS token、入口脚本由一个负责人整合，避免多个 agent 同时修改。
- 集成以公开入口跑真实项目为准，不能只分别调用底层函数。依赖契约变化时同步测试与文档。
- 控制依赖：优先使用现有 Node/Playwright、Python 与 PDF 工具；仅为必要解析/验证能力新增依赖，并锁版本。不要引入前端框架或重型构建系统解决静态手册问题。
- 不要求每改一个文件就跑所有测试；先跑相关最小检查，集成后跑完整契约与真实输出评测。

## 验收与“稳定酷炫”的测量

### 两类稳定性必须分开报告

**渲染稳定性**：同一作者源、资源与锁定环境重复导出，版面不漂移。至少分别在独立进程/浏览器上下文中导出两份 PDF，再用固定栅格器比较各页；测试资源缓存冷/热状态。忽略 PDF 时间戳等无关元数据，不忽略文字位置和图像差异。无字体安装依赖的系统级冷环境可单独验证，不能把未做的环境写成通过。

**创作品质稳定性**：不同独立 agent 执行相同原始 brief，是否都能产出合格成品。重复渲染一份精修 demo 不能回答这个问题。

### 独立生成基准

使用六类原始 brief，每类三次隔离的独立生成，共 18 个结果。每次从原始材料和正式 Skill 入口开始，不带前一次答案或具体页面坐标；记录模型/Skill/工具版本与资源条件。至少一类要求 24 页以上整册。

| 材料类型 | 必须覆盖的困难 |
|---|---|
| 真实照片宣传册 | 主图、辅助图、主体裁切、图注、跨页与装订 |
| 双语密集内容 | 长标题、正文行长、字重/字形、翻译对应、续页与目录 |
| 品牌产品册 | 真实品牌约束、表格/事实、家族一致与内容专属表现力 |
| 短文案与少素材 | 内容不足时的诚实处理、排印表现力、避免填空与杜撰 |
| 工作册/填写场景 | 真实可用的书写空间、标记/表单、不能自动缩没的功能区域 |
| 系列与修订 | 继承已有基因、跨期一致、局部改字/换图、源文件与在线编辑往返 |

每次保留首轮输出与全部失败；评测预算为首轮构建加最多两次自主修订，不通过无限返工补齐成绩。报告首轮合格率、预算内合格率、修订次数与失败类别。超预算继续制作的优质作品可作为单独案例，不能回填原基准成绩。

**拟定的交付门槛**：18/18 技术硬项通过；至少 16/18 视觉达到「可交付」，且每类至少 2/3 达到。视觉是否「优秀」另行统计，不能把技术通过包装成酷炫。以上是待执行的工程验收目标，不是当前成绩，也不是统计意义上的稳定性保证。

**审稿校准**：视觉「不合格 / 可交付 / 优秀」若由模型 reviewer 判定，先请用户或团队对一组样本人工评分（新旧输出都有，覆盖至少三类材料，不少于 6 份），记录模型与人工的一致率和主要分歧；按分歧修订审稿标准后，再给 18 份结果打分。基准报告同时列出人工抽查的份数与结果。

每份结果都审最终 PDF 的全部页面。原材料与条件相同的旧输出可作匿名并排参照，评价阅读体验、表现力与最弱页；不得通过给新方案更好照片或删掉难排文案制造优势。

另做一项有明确探索意图的结构自由测试，证明无新增 Python 布局函数也能完成不同构图。普通生成基准不要求三次结果都不同，不用差异度替代质量。

### 技术和产品验收矩阵

| 类别 | 必须留下的验证 |
|---|---|
| 页面与边界 | A4 精确物理尺寸、另一画布、出血/无出血、装订跨页、页数与页序 |
| 字体 | 实际字体与字重、完整字符覆盖、缺字体明确失败、无隐式系统回退 |
| 内容 | 原文完整映射；冻结模式；授权改写/翻译；分页指代；隐藏副本不能绕过 |
| 几何 | 长标题、长段落、定位/变换、合法叠放、内部裁切、图像消失、功能区被挤压 |
| 照片 | 有效 DPI、主体裁切、contain/cover、跨页连续性、来源与使用条件 |
