## 1. 诊断：不是“规则太多”，是“规则没有层级”

现在的 skill 把三类完全不同的东西写在了同一层：

1. **生产和保真的命**：网格、出血、字体嵌入、原文保真、数字出处、图片授权、门禁硬伤。
2. **已被验证的好例子**：8 基础版式、8 编辑变奏、10 摄影版式、4 主题、2 排印、6 套字体、purposes 页序、rhythms 节奏型。
3. **应该由模型判断的事**：这一本的概念、结构指纹、阅读入口、图文策略、页面节奏、什么时候该打破默认。

三层混在一起，模型读到的都是“必须”，结果只能是：**在菜单里选一个最安全的，尽快过 GATE**。版式目录从“参考”变成了“围墙”，`page-plan.md` 从“设计”变成了“填表”，创新无处记录，下一次又从零开始。

另一个直接证据：`SKILL.md` 已经 **15,335 字符**，超过 `selftest` 的 **12,000** 预算。规则在持续堆积，但没有分层和淘汰机制。

改造要解决的不是“少写规则”，而是让每条规则明确回答：**谁决定、能不能破、破了怎么记、记了之后怎么进化。**

## 3. 偏离机制：允许破默认，但不允许无记录

### 3.1 记录格式（写进 `page-plan.md` 每页小节）

```markdown
- 结构决策：目录选（T） / 组合（poster + 底部短栏） / 发明（见 proposals P03）
- 偏离：默认 T（照片在上、正文在下）
- 为什么默认不适用：原文只有 120 字，T 会留下约 20 行空纸面，页面没有第二个信息层
- 替代方案与收益：POSTER 满版 + 底部两栏短说明；先建立现场，再给任务
- 代价 / 风险：正文容量减少，图注必须并进短说明
- 影响页：P3–P4（与下一页的图文节奏连续）
- 验收点：5 秒内能说出“这是什么地方、读者要做什么”；图注不与主体相撞
```

四件事缺一不可：**默认、理由、代价、验收**。只写“这样更好看”不算偏离理由。

### 3.2 授权边界

| 偏离对象 | 谁批准 | 怎么记 |
|---|---|---|
| A 层任何一项 | 不允许；只能向用户说明限制 | `.qa/` 失败项 + 交付说明 |
| brief 级设置（主题 / 配色 / 字体 / 排印 / 画布 / 页数 / 品牌） | 用户 | 先改 `brief.md` 并记改动，再改 `book.yaml` |
| 页级版式 / 节奏 / 图文关系 | 模型自决 | `page-plan.md` 的偏离栏；视觉审稿复核 |
| 目录外的新结构 / 新组合 | 模型先做，视觉审稿后定去留 | `proposals.md` + 本页 `page-plan.md` |
| 规则本身要改 | 维护轮 | `dev/audits/` + 维护记录 |

### 3.3 偏离不是免责

- 偏离后仍要过 A 层和 gate；过不了就回退，不能把“这是我的设计选择”当豁免。
- 视觉审稿要明确回答：这个偏离**解决了什么**、**付出了什么**、**是否值得重复**。
- 连续两次独立出现、且视觉复核通过的偏离，才成为晋升候选；一次成功不等于规则。
- 用户明确否定的方向，记进“已知陷阱”，不再作为默认推荐。

### 4.2 `page-plan.md` 新增字段（草案）

在现有“页面任务 / 文案分工 / 展示方案 / 视觉主角 / 图文关系 / 验收重点”之上，补三项：

```markdown
- 页面 claim：这一页要让读者 ___，用〔S03 / 原文事实〕证明。
- 结构决策：目录选（layout） / 组合（哪些块） / 发明（proposals 编号）
```

## 6. 进化机制：让“这次的特殊处理”变成“下次的默认”

### 6.1 触发

- 累计 5 条 proposals；或
- 用户明确要求复盘；或
- 同一个问题在两个项目里重复出现；或
- 视觉审稿推翻了某个默认策略。

### 6.2 维护轮步骤

1. 读全部 `proposals.md`、`.qa/visual-review.md`、失败构建日志。
2. 分四类：
   - **引擎缺陷** → 进 `dev/audits/TODO.md`，写能复现的测试；
   - **参考骨架缺失** → 晋升为 `references/` 里的新模式或新条目；
   - **项目偏好** → 留在 brief，不升级为全局默认；
   - **坏主意** → 写入“已知陷阱”，保留反例。
3. 晋升必须带证据：项目、页面、视觉复核结论、代价。
4. 更新 `dev/audits/` 记录；必要时更新 `references/layouts.md` 或新建 `structure.md`。

### 6.3 度量（不追求“偏离越少越好”）

| 指标 | 含义 | 用途 |
|---|---|---|
| 默认命中率 | 未偏离 B 层的页数 / 总页数 | 判断默认是否够用 |
| 偏离成功率 | 视觉复核关闭的偏离 / 全部偏离 | 判断判断力，不判断服从度 |
| 返工率 | 因结构或文案重排的页数 / 总页数 | 判断流程成本 |
| 5 秒测试通过率 | 陌生读者能说出“是什么 / 给谁 / 做什么” | 判断概念是否成立 |

目标不是让默认命中率 100%，而是让**偏离有理由、有结果、可复用**。

## 7. 试点与验收

### 7.1 试点范围

选 3 本，覆盖不同内容形状：

1. 一本照片主导（如 photo 主题）。
2. 一本文字主导（如 editorial / 无图）。
3. 一本改版（已有成品，验证不丢已认可内容）。

### 7.2 验收标准

- 3 本都有概念句、结构指纹、逐页 claim。
- 每本至少 1 处 B 层偏离，写清默认 / 理由 / 代价 / 验收点。
- 视觉审稿能明确回答偏离是否值得，而不是只写“通过”。
- 产出与改造前相比，至少有一处结构选择不同，且不是为不同而不同。
- 全部 GATE PASS；`selftest.sh` 通过；`SKILL.md` ≤ 12,000 字符。
- 至少 1 条“默认不适合”的发现进入 `dev/audits/`，作为下一轮晋升或陷阱记录。

### 7.3 不通过的信号

- 概念句可以套在任何同类机构上（竞品测试失败）。
- 偏离栏写成“这样更好看”，没有代价和验收。
- 视觉审稿仍然只复述 GATE PASS。
- 为了让偏离成立，偷偷改 A 层（字号、网格、保真、授权）。

## 8. 风险与对冲

| 风险 | 对冲 |
|---|---|
| 自由度变大，质量方差变大 | A 层不动；视觉审稿 + 5 秒测试；试点先小范围 |
| 偏离变成偷懒的借口 | 偏离必须写代价与验收；A 层不可破；审稿可回退 |
| 概念句变成新的八股 | 竞品测试；维护轮把空洞概念写入“已知陷阱” |
| 文档变长，SKILL.md 更超预算 | 细节放 references / workflows；§2 只留分层与裁决 |
| 没有引擎支持，“自由区”名不副实 | 本阶段明确只做“目录内选择 + 既有块组合 + proposals 记录”；COMPOSE 等 E2 |
| 维护轮没人做 | 绑定触发条件（5 条 proposals / 用户要求 / 重复问题），写进 `dev/maintenance.md` |
